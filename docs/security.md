# 安全模型与已知边界

| 边界 | 执行措施 | 验证 |
|---|---|---|
| 用户权限 | Argon2id 密码；随机会话 token 仅保存 SHA-256；7 天过期；HttpOnly/SameSite Cookie；资源查询始终绑定 user_id | 注册/登录/注销、跨用户 Trace 404 |
| CSRF / 输入 | 修改请求须有自定义 header；存在 Origin 时必须匹配；16 KB 请求体限制含流式请求；Pydantic extra=forbid | CSRF/格式/时区测试 |
| 工作区 | 每用户随机 ID 子目录；拒绝绝对路径、`..`、反斜杠、ADS、Windows 保留名、隐藏路径、链接和 reparse point | 路径攻击、用户隔离测试 |
| 命令 | `bash` 工具真实启动进程；仅 pwd/ls/cat/head/wc；解析 argv、禁止 flags/多路径/重定向/管道/替换；shell=False；5 秒超时；环境不继承 API Key | 真正 cat/wc 执行与危险命令拦截 |
| SSRF | 固定 HTTPS 新闻域名；仅固定 RSS 返回的当前运行 URL；校验每次重定向；解析 IP 必须 public；连接固定已验证 IP，TLS SNI 和证书仍验证域名；不继承代理 | 私有 IP、伪域名、端口、scheme 拦截 |
| Prompt Injection | 系统提示标明新闻/文件不可信；去除 script/nav/form；常见指令模式隔离；无身份/收件人参数；模型写入数据不成为系统消息 | 恶意正文隔离、未知工具与身份注入拒绝 |
| 事实依据 | 模型不能自造文章 ID；摘要中禁止 URL；服务端构建来源链接；证据片段必须在抓取正文中逐字存在；SHA-256 与抓取时间留存 | 假引用拒绝、真实抓取证据 |
| 推送幂等 | 日报 user/date 唯一；发件箱 digest/channel 唯一；站内通知事务唯一；SMTP 原子 pending→sending；提交后异常为 uncertain，绝不自动重发 | 并发入队、重复消费、模糊确认失败测试 |
| 成本与可用性 | 每用户单活跃任务、触发限流；模型轮数18、工具调用45、时间300s、上下文280K字符；读取32K字符/写入128KB/工作区2MB；响应2MB | 无限循环预算、限量与取消测试 |
| 密钥/审计 | .env/data/private 被 gitignore；Trace 去除 provider reasoning_content；密钥字符串与 sk-pattern 脱敏；HTTP 库异常只记类型 | Trace 脱敏测试 |

## 不能作出的保证

- Prompt Injection 防护是多层风险控制，关键词隔离不是完备检测器；恶意但未命中的文字仍可能影响新闻选择或摘要。模型无法因此获得任意 shell、任意网络、跨用户或任意收件人的权限。
- 逐字引用存在只能证明摘要有可核查材料，不能证明语义完全正确。摘要明确标为 AI 生成，原文证据与来源始终可查。
- SMTP 协议没有端到端 exactly-once 事务。发送后连接断开时，无法判定对端是否收妥，保留 uncertain，需检查邮件服务器日志。站内通知可通过 SQLite 事务保证唯一。Message-ID 是辅助追踪，不代表收件方一定去重。
- 文件隔离是应用层能力边界，**不是用于运行恶意代码的操作系统沙箱**。部署目录应仅由服务账号写入；具有宿主机文件修改权限的人不在远程用户威胁模型内。生产可追加独立容器、只读根文件系统和网络出口策略。
- 本地应用注册不提供邮箱所有权验证、密码重置或管理员管理；公开互联网部署前应接入可信身份服务和邮箱验证，SMTP 账号也应配置配额和反滥用策略。开发阶段邮件默认关闭。
- 单实例 Worker 顺序执行任务；服务停机时不会运行。重启只补当天到点的定时任务，不重放多天积压；失败的每日 slot 不自动无限重试，可以手动发起新任务。
- 订阅撤销在入队和开始投递前重读；已经开始的 SMTP 提交无法撤回。修改偏好不重写已有日报。

## 恢复操作

同一 Agent 运行可在推送入队前扩充日报草稿，沿用同一个 digest_id；一旦有投递记录，正文变为不可修改，防止站内与邮件内容不一致。保存工具始终返回持久化后的实际条数，而不是提交参数的条数。

生成失败：查看 Trace，修复来源/凭据后手动再生成。摘要已存但推送未排队：`POST /api/digests/{id}/send`。SMTP 配置错误修复后，使用同一接口显式重试 failed 投递；sent/sending/uncertain 不会重新入队。不要手动把 uncertain 改为 pending，除非先在邮件服务器完成核查。
