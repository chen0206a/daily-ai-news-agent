# 3 分钟演示脚本

## 演示前准备（不占 3 分钟）

1. 根据 README 安装并配置 `.env`，不要把密钥投屏。
2. 执行 `python scripts/live_e2e.py`，检查 `evidence/live-e2e.json` 的 status=completed。
3. 启动前后端，在本机私有文件 `evidence/private/demo-login.json` 读取演示账号后登录。该文件不提交，不在演示中打开。
4. 打开三个窗口：前端、代码 `backend/app/agent/graph.py`、测试报告。真实生成可能受网络和模型响应影响，先准备好刚运行完成的真实 Trace，而不是硬等 3 分钟。

## 00:00–00:25 / 产品与问题

画面：登录后的日报工作台。

讲解：“这是 Daily AI News Agent，界面名为 Daybreak。它用 Python、LangGraph、DeepSeek、FastAPI、Next.js 和 SQLite，根据用户订阅自动查找、阅读并生成 AI 新闻日报。这里的日报来自真实联网抓取，右侧是用户的信源与送达设置。”

## 00:25–00:50 / 订阅与任务

画面：订阅配置，修改主题，展示语言、新闻条数、时间范围、IANA 时区、站内与邮件开关；点击保存。

讲解：“偏好按用户持久化，每日任务按用户本地日期去重。邮件仅发送到当前账户邮箱，模型不能指定收件人。没有 SMTP 配置时会如实记录失败。”

## 00:50–01:30 / 真正的 Agent Loop

画面：Agent Trace，展开两次 `search_news` 与若干 `fetch_article`。然后切到 graph.py 的 conditional edges。

讲解：“这里不是写死的搜索、摘要、发送流水线。图只有模型节点和工具节点，DeepSeek 使用 tool_choice=auto 自己选择工具与顺序，工具结果再回到模型。页面展示实际供应商响应 ID、Token 用量、参数、耗时和工具结果。工具失败也会回给模型，让它选择怎么处理。轮数、工具数和超时限制防止无限循环。”

注意：按当前真实证据讲轮数，不把离线脚本模型称为真实模型。

## 01:30–02:00 / 来源与安全

画面：返回日报，展开一条“原文证据与来源指纹”，打开原始新闻链接。

讲解：“文章 ID 来自本轮实际抓取，证据片段必须在原文中存在，链接由服务端生成，抓取时间和内容哈希保留。外部正文只当作不可信数据；可疑提示注入会隔离。文件工具拒绝越界路径，bash 只能执行五种只读命令，不开放 shell。”

## 02:00–02:30 / 测试与可靠投递

画面：后端测试结果和浏览器测试报告，展示对应安全测试文件。

讲解：“测试包含工具真实执行、命令和路径攻击、用户越权、恶意文章、Agent 不同调用顺序、预算、定时去重、SMTP 与站内幂等。SMTP 发送后若确认丢失会标记 uncertain，不自动重发，避免把协议无法保证的 exactly-once 包装成保证。”

## 02:30–03:00 / 交付

画面：历史日报、通知、README 的快速启动与证据入口。

讲解：“交付包括完整源码、依赖锁文件、环境模板、两张流程图、测试和真实运行证据。站内推送已端到端验证；SMTP 通过本机真实协议测试，外部收件箱需要配置后验证。公开部署前要补邮箱身份验证与生产访问控制；单机笔试场景一条启动命令即可演示。”
